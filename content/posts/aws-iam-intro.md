## 什么是 IAM？

AWS Identity and Access Management（IAM）是一种 Web 服务，帮助您安全地控制对 AWS 资源的访问。

IAM 主要做两件事：

- **身份验证**（Authentication）：确认你是谁
- **授权**（Authorization）：允许你做什么

## 核心概念

### 根用户

当您首次创建 AWS 账户时，最初使用的是一个对所有 AWS 服务和资源拥有**完全访问权限**的登录身份——称为 **AWS 账户根用户**。

> ⚠ **强烈建议不要使用根用户进行日常任务。** 应为管理员、开发人员等创建 IAM 用户。

### IAM 用户

IAM 用户是 AWS 账户内的一个身份，代表一个人或应用程序。每个用户有独立的凭证（密码或访问密钥）。

创建时默认没有任何权限，需要通过策略显式授权。

### IAM 用户组

用户组是一组 IAM 用户的集合。把策略附加到组上，组内所有用户自动继承权限。

```
┌─────────────┐
│  开发者组   │  ← 附加策略
├─────────────┤
│  用户 A     │
│  用户 B     │  ← 自动获得组权限
│  用户 C     │
└─────────────┘
```

### IAM 角色

角色与用户类似，也是具有权限的 AWS 身份，但**不与特定人员绑定**。角色可以被以下实体代入（Assume）：

- AWS 服务（如 EC2、Lambda）
- 其他 AWS 账户的用户
- 联合身份用户（SAML、OIDC）

角色通过**信任策略**控制谁可以代入，通过**权限策略**控制代入后能做什么。

### 联合身份

如果您已经有一套身份系统（如 Microsoft AD、Okta、Google），可以使用**联合身份验证**让用户通过现有身份登录 AWS，无需创建 IAM 用户。

支持的标准：**SAML 2.0**、**OIDC**、**Web Identity Federation**。

## 访问管理

### 策略（Policy）

策略是 AWS 中的 JSON 文档，定义权限。将其附加到身份或资源后，决定允许或拒绝哪些操作。

```json
{
    "Version": "2012-10-17",
    "Statement": {
        "Effect": "Allow",
        "Action": "s3:GetObject",
        "Resource": "arn:aws:s3:::my-bucket/*"
    }
}
```

### 基于身份的策略

附加到 IAM 用户、组或角色的策略：

- **AWS 托管策略**：AWS 创建和维护，适合新手
- **客户管理策略**：您在账户中自行创建和管理
- **内联策略**：直接嵌入单个身份，不推荐常规使用

### 基于资源的策略

附加到 AWS 资源上的策略。S3 存储桶策略是典型例子：

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Principal": "*",
            "Action": "s3:GetObject",
            "Resource": "arn:aws:s3:::public-bucket/*"
        }
    ]
}
```

IAM 角色本身也是一种基于资源的策略——**信任策略**定义了哪些主体可以代入该角色。

### 策略评估逻辑

AWS 按以下逻辑决定最终权限：

1. 默认**隐式拒绝**所有请求
2. AWS 组织中的**服务控制策略（SCP）**可以覆盖
3. 如果有**显式 Deny**，直接拒绝
4. 如果有**显式 Allow**，允许
5. 否则**隐式拒绝**

> 一句话：**Deny 优先于 Allow**。

## 权限边界（Permission Boundary）

您可以使用**权限边界**来限制 IAM 用户或角色的最大权限。即使附加了更宽松的策略，实际有效权限也不会超出边界。

```
用户策略：          s3:*   ec2:*
权限边界：          ec2:*
────────────────────────────
有效权限：          ec2:*
```

## 访问分析（Access Analyzer）

IAM Access Analyzer 帮助您识别意外共享的资源，分析未使用的权限以精简策略。

- **外部访问分析**：免费，检测可被外部账户访问的资源
- **未使用访问分析**：付费，识别未使用的服务权限

## 安全最佳实践

| 实践 | 说明 |
|------|------|
| 锁定根用户 | 启用 MFA，妥善保管，日常不使用 |
| 最小权限原则 | 只授予完成任务所需的最小权限 |
| 使用用户组 | 通过组管理权限，不要直接附加给用户 |
| 启用 MFA | 对所有用户强制启用多因素认证 |
| 使用角色 | 用 IAM 角色代替长期访问密钥 |
| 定期审计 | 使用 Access Advisor 检查未使用的权限 |
| 使用条件键 | 在策略中增加 IP、时间、MFA 等限制 |

## 服务可用性与计费

- **最终一致性**：IAM 更改需要几秒到几分钟传播到所有区域
- **免费**：IAM、IAM Identity Center、AWS STS 本身不收费
- **集成广泛**：IAM 几乎与所有 AWS 服务集成

## 总结

| 概念 | 要点 |
|------|------|
| 根用户 | 完全访问，仅供初始化使用 |
| IAM 用户 | 长期身份，每人一个账号 |
| IAM 组 | 批量管理权限 |
| IAM 角色 | 临时授权，服务或跨账户使用 |
| 策略 | JSON 定义权限，核心管控手段 |
| 评估逻辑 | Deny 优先，Allow 通过，默认拒绝 |
